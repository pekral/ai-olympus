# Changelog

All notable changes to `laravel-agent-skills` will be documented in this file.

## [Unreleased]

- ⚡ **Changed**: review/fix loops now use a **cheap diff-scoped gate per iteration and one full build at the boundary** (#65), instead of a full `composer build` on every iteration. A new *Loop gate vs. final gate* section in `@skills/resolve-issue/references/quality-gates.md` splits the two: a **loop iteration** runs only the changed-files fixers / checkers / coverage (the project's `check:changed` / `test:coverage:diff` equivalents) and **skips the dependency/skill reinstall** (`agent-skills install --force`, `composer install`) — nothing the loop does changes them, so reinstalling each iteration was pure latency; the **final gate** runs the full `composer build` (install + full-suite `--min=100`) once before push, and also whenever the change is broad (shared/core/config surface or >~10 files, the `apollon` high-risk heuristic). `@skills/process-code-review/SKILL.md` wires both halves — loop gate in the Review loop, full final gate in Finalization. Crucially the lightening **never removes** the boundary build: it is the gate that guarantees a merge never lands with a broken project (**issue #75** is preserved, not weakened). Pinned by a new test. Per issue #65.

- ✨ **Added**: code-review output must **state only verified facts, never assumptions** (#74) — a new *Output Rules — Truthful reporting* section in `@rules/code-review/general.mdc`, referenced from every CR wrapper via `@skills/code-review/SKILL.md`. The review is the input to a merge decision, so a confident-but-wrong line is worse than an omitted one: it authorizes a merge the evidence does not support. The rule governs the **whole** output, not just `## Findings` — findings state only what was reproduced (not "this could break"), counts are the real surviving counts for the head commit, **a check is reported as run only when it ran** (a delegated `security: owned by athena` records a delegation, not a delivery, and must link the delegate's real output — the merge gate verifies it exists), uncertainty is labelled rather than laundered into fact, and no `file:line` / test result / coverage figure / rule citation is fabricated. A review that publishes an unverified claim as fact is treated as non-converged and must be corrected before the merge gate consumes it. Pinned by a new test. Per issue #74.

- ✨ **Added**: code review now flags **explanatory comments and documentation that only restate the code** (#53) — a new *Explanatory comments and docs that restate the code* bullet in `@rules/code-review/general.mdc` Core Analysis Walk-through, enumerated in `@skills/code-review/SKILL.md` so every CR wrapper inherits it. It flags, on touched lines, a comment narrating a self-evident statement, a docblock that only repeats the typed signature, or a `.md` / class docblock added solely to describe what the code does — the fix is to delete it and, where the code was unclear, make it clear (rename, extract, DTO) rather than annotate it. Three carve-outs stay because the code provably cannot carry them: comments / ADRs explaining *why* not *what* (rejected alternatives, non-obvious trade-offs), domain glossaries, and navigation markers (the thin `@see` / `@rules/...` reference strings forming reader paths). **Minor** for a redundant comment; **Moderate** for a doc file that narrates behaviour, since it drifts into a second, lying source of truth. Gated against Simplicity First so the two never double-report. Pinned by a new test. Per issue #53.

- 📝 **Changed**: `resolve-issue`'s body is back under the skill-check token limit (#59) — the long-standing `body.max_tokens` WARN (estimate had drifted past 5000, and the repository-ownership guard's JIRA/Bugsnag additions pushed it higher) is resolved by extracting three self-contained procedures to `references/` — `deferred-follow-up.md` (the deduplicate/file/verify/cross-link filing steps), `pre-existing-issue-handling.md` (the categories, commit conventions, and per-type coverage workflow), and `phase-planning.md` (the commit-plan step-by-step) — each replaced in the body by a short summary plus a pointer, and by compacting the *Reopened task* deep-pass and the step-6/7 problem-analysis prose. No procedure changed; the byte-pinned fragments the content tests assert now live in the reference files, and the tests read them there. `## References` lists the three new files. Per issue #59.

- ✨ **Added**: code review now flags a **translation key referenced but defined in no locale** (#37) — a new *Referenced translation key must exist* walk in `@rules/code-review/general.mdc`, next to the existing *Translation completeness* walk. The completeness walk already covered a key present in the default locale but missing from another, and a hard-coded literal where analogous code uses `__()`; it did **not** cover a call like `__('user.profile.saved')` whose key exists in **no** locale file. Laravel does not fail on that — `__()` returns the key string verbatim, so the user is shown the dotted identifier as if it were a sentence, and it slips past every gate (the code compiles, nothing was added so parity is clean, and the call does go through `__()`). The new walk resolves both key layouts (dotted `lang/{locale}/{file}.php` and full-sentence `lang/{locale}.json`), refuses to guess at runtime-assembled keys, and carries an explicit scope boundary so it never double-reports with the completeness walk. **Moderate**, **Critical** on a primary-flow surface. Pinned by a new test in `tests/Installer/CodeReviewContentTest.php`. Per issue #37.

- 📝 **Changed**: `git-workflow`'s **Conflict resolution** section now leads with intent rather than commands (#50), adapting the approach from [mattpocock/skills — resolving-merge-conflicts](https://github.com/mattpocock/skills/blob/main/skills/engineering/resolving-merge-conflicts/SKILL.md). The section was a bare command list; it now walks the actual decisions a conflict forces — **find the primary source of each side** (commit / PR / issue) before touching a marker, **preserve both intents where compatible** and record the trade-off where they are not, and **never invent a third behaviour** in a merge commit that no reviewer sees against either parent. Two traps are named that the old list glossed: **`--ours` / `--theirs` are inverted under `rebase`** relative to a merge (reaching for them from muscle memory mid-rebase drops a branch's own work), and **aborting is a decision about the merge, not an escape from a hard conflict** — correct for a wrong base/branch/scope, wrong as a way to hand the same conflict to the next person with less context. Pinned by a new content test in `tests/Installer/SkillsContentTest.php`. Per issue #50.

- ✨ **Added**: a **shared repository-ownership gate** so no skill can act on a GitHub issue/PR belonging to another repository. `skills/_shared/assert-current-repo.sh` compares the reference against the current checkout and exits `4` on a mismatch, `5` when ownership cannot be proven; every non-zero exit is a hard stop and the deterministic loader's "exit 2/3 → fall back to the MCP server" convention explicitly does **not** apply — there is no fallback for an ownership verdict (code `3` is left unused for exactly that reason). Wired into the nine skills that act on a GitHub reference: `merge-github-pr` (which had no repository check at all despite merging), `process-code-review`, `code-review-github`, `code-review-jira`, `code-review-bugsnag`, `prepare-issue-context`, `tester-cookbook`, `analyze-problem`, and `resolve-issue` (whose prose gate now points at the shared script instead of restating it). Deliberately **not** wired into `security-threat-analysis` (reads `github.com/advisories/<GHSA>` as an external threat source), `code-review`, `pr-summary`, and `assignment-compliance-check` (their reference comes from the checked-out branch or an already-validated wrapper, never from the caller); a test pins both lists so the split stays deliberate. Ownership is resolved from **every** remote through `git remote get-url --all` / `--push --all`, which applies `insteadOf` / `pushInsteadOf` and returns the URL git would actually contact — so the fork workflow (`origin` = fork, `upstream` = the repo the PR lives on) and `pushurl` setups resolve correctly, unlike a raw `remote.origin.url` read. The `gh repo view` fallback applies **only** to a checkout with no remotes at all: consulting it after a parse failure would let gh's own parser silently repair the verdict and hide the gap. Two review rounds (`argos` + `athena`) drove the parser to a single canonical implementation shared by the reference and remote sides, closing path traversal (literal, percent-encoded, and double-encoded), an `@` in the path being mistaken for userinfo, and an SSH host alias honoured over https (`github.com-evil.example` is registrable). Behaviour is proven by a `--self-test` in the script itself covering every remote URL form git accepts, both traversal families, the look-alike hosts, the fork / insteadOf / pushurl setups, and each closed bypass (the `scan-attachments.sh` precedent) — and **`composer check` now actually runs it**, via a new `shell-self-tests` script that also covers `scan-attachments.sh`'s own long-dead self-test; both previously passed while nothing executed them, so a mutation flipping `exit 4` to `exit 0` left the build green. Per user request — *uprav si skilly tak, aby se vždy kontrolovala správná github issues pro aktuální repository*.

- ⚡ **Changed**: the CR pipeline no longer runs the **security pass twice**. All four wrappers (`code-review`, `code-review-github`, `code-review-jira`, `code-review-bugsnag`) skip their always-run `@skills/security-review/SKILL.md` step when the caller sets `SECURITY_OWNER=athena`, which `argos` does whenever `athena` is dispatched alongside it. The always-run set is strictly sequential, so the duplicate pass was pure latency rather than extra coverage — `argos` runs measured 14–19 minutes against `athena`'s ~12. The flag is **opt-in and fail-safe**: unset, the inline pass runs exactly as before, so coverage can never drop because a caller forgot to set it, and a run without `athena` is unchanged. A skipped pass is declared on the summary line (`security: owned by athena`) so a PR comment never implies a review that did not happen there. Agent `effort` is deliberately **not** lowered — `argos` and `athena` are the merge gate, and issue #64's own analysis keeps them at `max`. Pinned by a content test. Per user request — *CR trvá déle než by mělo, zkus upravit agenty tak aby dodrželi stejnou kvalitu, ale byli rychlejší*.

- 🐛 **Fixed**: the merge gate now **verifies a delegated security review actually arrived** instead of trusting the delegation token. `security: owned by athena` records that the inline pass was skipped — it says nothing about whether the delegate ever reported, so a PR could pass the hard `0 Critical + 0 Moderate` gate with **zero** security coverage while being positively marked as covered. Not hypothetical: a security pass that dies mid-run (API error, session limit, cancelled agent) leaves exactly that state, and it occurred during this PR's own review. `merge-github-pr` now locates athena's security comment and applies the same `updatedAt` staleness rule as the code-review comment, and the Summary token must carry the URL of that comment so a token without a link is itself the visible gap.

- ⚙️ **Changed**: the **GitHub Actions billing exception now substitutes evidence rather than waiving it**. A billing / account-limit failure means the jobs never executed, so it carries no information about the code — treating it as a red build blocks every merge for a reason unrelated to quality. The exception is therefore no longer gated on the merge being "explicitly requested"; it requires a **green local `composer build` on the exact head commit**, recorded in the merge report, plus confirmation from the run's annotations (`gh api repos/<owner>/<repo>/check-runs/<id>/annotations`) that the jobs genuinely never started — a real failure and a never-started job are indistinguishable in the checks list. Without passing substitute evidence the exception has no effect. It never converts *we could not measure* into *it is fine*; it allows a different, equally strict measurement. Per user request — *Pokud je v github actions problém s billing tak to ignoruj pokud lokální build je ok*.

- ✨ **Added**: agents and skills that create a new tracker issue now **always select the single most relevant label from the target system's existing labels** and apply it (#54). New section `## Label newly created tracker issues` in `rules/compound-engineering/general.mdc` (placed between *File deferred points as follow-up tracker issues* and *What Not To Do*) is the single home for both the principle and the per-tracker mechanics — unlike its two neighbouring sections, this contract has four call sites, so the mechanics live in the rule itself instead of one executor skill. The heuristic loads the target tracker's full label list first (GitHub: `gh label list --json name,description --limit 200` — the CLI defaults to only 30 labels; JIRA: labels carry no description, so candidates are harvested via `acli jira workitem search --jql "... labels IS NOT EMPTY ..."` and matched on name only; Bugsnag inherits the GitHub mechanics since it files as a GitHub issue), excludes three generic non-content classes (workflow/state/structural, verdict/triage, audience — recognized by name/description, never hardcoded to this repo's own label set such as `Resolve_by_AI`, `duplicate`, `good first issue`), and picks the single best-matching content candidate (`bug`, `enhancement`, `documentation`, …) by comparing name + description against the new issue's title + body. When nothing fits, the issue is created **without** a label rather than forcing a wrong one or inventing a new one — the rule's only sanctioned exception to "never create a new label" is the pre-existing structural `EPIC` label from `create-issues-from-text`'s *EPIC parent & sub-issues*. The new mechanism is purely additive to the existing `EPIC` / `Resolve_by_AI` (backlog + claim) / `ready for review` label logic, which is unchanged. Four call sites now carry a one-line reference to the rule: `skills/create-issue/SKILL.md` (step 3), `skills/create-issues-from-text/SKILL.md` (step 3), `skills/resolve-issue/SKILL.md` (*Deferred-item follow-up issues*, step 2's GitHub/JIRA/Bugsnag bullets), and `agents/metis.md` (step 3, publishing the analysis plan issue).
