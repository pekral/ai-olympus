# Backlog-only intent (a request about the queue, or a subject too broad for one PR)

Extracted word for word from `agents/krang.md` step 3 so the orchestrator does not carry it on every run. **Loading trigger:** step 3 classifies the request as *Backlog-only intent*: the user asked about the queue rather than about a task, or step 1 already classified the resolved subject as *Too broad for one PR*. In the text below, *step 1*, *step 2*, *step 7*, *above*, and *below* refer to `agents/krang.md`, and *Backlog tier — triage and decomposition, run inline* is its section of that name.

**this branch is the backlog tier's single executor** — step 1 classifies and routes, and the work happens here, once, after step 2 has written the brief that *Decomposition mode* reads. Run the matching mode of *Backlog tier — triage and decomposition, run inline* above **in your own context**: for a subject step 1 classified as *Too broad for one PR*, **run decomposition inline**, in your own context, which splits it into independently deliverable tracker issues through `@skills/create-issues-from-text/SKILL.md`, each carrying its `## Dependencies`.
**When the split is an EPIC parent with sub-issues, create nothing until a human approves it** (`@rules/compound-engineering/backlog.md` *Decomposition mode* step 3): present the confirmation package — the parent, one line per sub-issue, the dependencies, the resolve order — report `Breakdown proposed — awaiting approval`, and stop. The original request is not that approval and neither is silence. A flat set of peer issues is unaffected and is created as before.
That run ends at the created issues and must never carry one of them onward in the same run: each piece re-enters as its own `krang` run, which is the whole reason the subject was split.
Report `Triage done` / `Breakdown done` with its result — for a decomposition, the created issues in resolve order — then **run *Run cleanup*** (the checklist written down in step 7, invoked here) **and stop**: read the audit total for your report's `Audit:` line first, then `rm -f "$BRIEF" "${BRIEF%.md}.dispatches" "${BRIEF%.md}.audit" "${BRIEF%.md}.routing"` — under *Run cleanup*'s `## PID` ownership gate, never unconditionally.
This branch dispatches nobody and opens no pull request, and — like the analysis-only stop below — it never acquired the working-tree write-lock and never dispatched a CR pass, so those four scratch files are the whole of what it owes. When both apply (a broad subject arriving while the backlog is untriaged), run *Decomposition mode* first and report the triage as a recommendation, so the user's actual request is answered rather than deferred behind housekeeping.
