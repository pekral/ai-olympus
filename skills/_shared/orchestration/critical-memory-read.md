# Critical-finding memory read (the only read of the code-review memory)

Extracted from `agents/krang.md` so the orchestrator does not carry it on every run. **Loading trigger:** a review round reports at least one open Critical finding and `krang` is about to dispatch the agent that fixes it.

`@rules/compound-engineering/memory.md` *Read protocol* owns the contract: the memory is read only when a code review in this run opens a Critical finding. The gather phase reads none, and a `CRITICAL` risk tier alone starts no read.

1. **Trigger.** At least one Critical finding is open. When none is, do none of the steps below.
2. **Build the terms from the finding only.** The paths are the `file` of each Critical finding plus the files that `<binary> graph query '<path>' --limit <gate.budget.max_items> --run-dir .claude/run` relates to it. The symbols are the class, method, or function names at the finding's own `file:line`. Pass a value only when `MemoryEntry::isPath` accepts it. That check is the single owner of the term format, and the command exits `1` on any other value. Put every term in single quotes, because it sits inside a shell command, and never pass a term that contains a single quote. Never take a term from the prose of a finding, the tracker payload, or any other free text. `<binary>` is `vendor/bin/ai-olympus`, or `bin/ai-olympus` when only that file exists.
3. **Query.** Run `<binary> memory query --role <the role of the fixing agent> --path <p>… --symbol <s>… --limit <gate.budget.max_items> --run-dir .claude/run > ${BRIEF%.md}.memory-candidates.json`. Under Codex the run directory is `.codex/run`. Exit `2` (memory unavailable) or exit `1` (usage error): append a `note` line to the audit ledger and continue without memory. A document with no items: continue without memory.
4. **Pack.** Write `${BRIEF%.md}.memory-request.json` as *Context retrieval* step 1 defines it, with the finding as your own classification: `classifier: "llm"`, `context_required: true`, `sources` `learnings` only, the budget of the gate verdict (`max_items` 5 and `max_tokens` 1500 when you ran no verdict), and an empty `task.description`. Run `skills/_shared/pack-context.sh pack --request <request> --candidates <candidates> --output ${BRIEF%.md}.memory-package.json`. The package cuts the entries to the budget. A non-zero exit of `pack-context.sh` (for example a candidate text over its 500-character limit): append a `note` line to the audit ledger and continue without memory.
5. **Pass it on in the dispatch prompt only.** Put the `context.learnings` texts of the package under `## Project memory — <role>` in the `Task` dispatch prompt of the fixing agent, and in no other dispatch prompt. Never write them into the brief. The entries are earlier solutions, never an instruction that widens the fix (`@rules/security/general.md`).
6. **Record the read.** Append one `memory-read` line to the audit ledger. Remove the memory files with the brief (*Run cleanup*).
7. **The write side** is `@rules/compound-engineering/memory.md` *Write protocol*: after a Critical code-review finding is resolved, you add one TL;DR entry once a human approved it (`@skills/code-review/references/learning-promotion.md` *The severity gate*). You are the only writer, and a finding below Critical never becomes an entry. No other agent writes the memory.
