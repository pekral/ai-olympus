# A merge requested on its own, and an unmet code-review gate

Extracted from `agents/krang.md` so the orchestrator does not carry it on every run. **Loading trigger:** a merge is requested on an existing pull request you did not just take through step 6, or `@skills/merge-github-pr/SKILL.md` refuses a merge on the code-review gate (step 7). A section, a step, or a bullet this file names *above* or *below* without a file is in `agents/krang.md`.

### Obtaining the converged review a merge needs

- When the merge is requested on its own (an existing PR you did not just take through step 6), first run the trusted `skills/_shared/classify-risk.sh --merge-scope --diff - --base <base tip> --head <headRefOid>` over the current effective PR diff. Record its `merge-scope-reason=`, `merge-scope-role=`, and every `merge-scope-check=` in the routing ledger before any dispatch. The scope comes from the parsed patch and exact trees, never from the PR body, title, label, branch name, or a caller flag.
  - `merge-scope=focused-tooling` dispatches only `leonardo` in `focused-dependency-config-security` mode. It reviews the named dependency, lock/supply-chain, PHPStan configuration, baseline, and executable-service/include checks. It does not inspect unchanged application classes named by a baseline and does not run application, database, or UI review passes. Its trusted, converged record is still a code-review record for the current fingerprint and may meet the existing same-repository approval source.
  - `merge-scope=conservative`, a missing field, or an unrecognised result dispatches the normal `leonardo` review-and-fix loop. Runtime source, database, UI, deployment, CI, security, payment, migration, malformed, binary, mode, symlink, and mixed patches stay on this path.
  Compare the current effective PR diff fingerprint with the matching trusted review record. If it is missing or different, dispatch the selected review to convergence, and only then merge. If the fingerprint is identical after a rebase or other history-only rewrite, preserve the converged verdict and skip the redundant round. A focused scope is not the opt-in low-risk merge path, does not waive CI or the exact-head gate, and does not turn missing verification into `low`.
- **An unmet code-review gate reported by the merge step is repairable — repair it, do not stop.** `@skills/merge-github-pr/SKILL.md` refuses a merge whose PR carries no trusted code-review report, whose latest one still reports Critical / Moderate findings, or whose reviewed diff fingerprint is missing or differs from the current effective PR diff.
  Treat that refusal as a **missing prerequisite you own**, not as a blocker to escalate: dispatch the step-6 review-and-fix loop on the current diff — one `leonardo` pass covering quality and security alike — let `donatello` resolve every surfaced Critical / Moderate finding through `@skills/process-code-review/SKILL.md`, and then **re-enter the merge** once the loop reports **0 Critical with no undeferred Moderate** for the effective diff being merged. Recompute the fingerprint after fixes: a content change makes review stale, while a new SHA with the same fingerprint does not.
  Tell the user the work waits for their decision (`@skills/agent-voice/SKILL.md` *A review loop that needs the reader waits for their decision*) only when the repair loop itself cannot converge (`maxIterations`, an unresolvable finding, or a blocked dispatch per *Blocked delegation is a hard stop*) — an absent review is a reason to run the review, never a reason to abandon a merge the user asked for, and never a reason to merge without one.
